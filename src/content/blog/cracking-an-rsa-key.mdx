This was created for the Bitsight finding that says a 1024-bit long RSA key is
too short.

## Basics

The public key has two parts, the modulus and the public exponent. The modulus
is generated by multiplying two large numbers; finding these numbers is called
the factorization problem. Once found, the private key can be generated.

How RSA works: [here](https://www.geeksforgeeks.org/rsa-algorithm-cryptography/).

### Notes for CTF

CTF may require you to crack keys. Typically these keys are generated in a way so
it is easier to bruteforce the primes.
[CTF-specific tool.](https://github.com/RsaCtfTool/RsaCtfTool/tree/master)

For example, if the two prime numbers are close to each other, the fastest algo
is [Fermat](https://github.com/d4rkvaibhav/Fermat-Factorization).

## Finding the factors

### Classical computing

Multiple factorization algorithms. Finding factors for numbers that are longer
than 1024 bits is not feasible.

- GNFS (the general number field sieve).

#### yafu

[github.com/bbuhrow/yafu](https://github.com/bbuhrow/yafu/tree/master)

This CLI tool uses multiple algorithms and claims to be the fastest to find the
prime factors.

#### b4den

```bash
docker pull b4den/rsacrack
```

### Quantum computing

Shor's algorithm is the most efficient. It is not fault tolerant; there are not
enough qubits in publicly available quantum computers to work on real keys.

Current record holder is China: in December 2022, the 48-bit factorisation
261980999226229 = 15538213 × 16860433.
